# What on-disk shapes count as a Wayfinder map

Type: research
Status: resolved
Blocked by:

## Question

Given a **Project** folder on disk, what artifacts count as a Wayfinder **Map**, **Ticket**, research note, spec, or prototype — for the local-markdown tracker and for GitHub/GitLab trackers? What must the **Reader** scan, parse, and show in the tree so Khaled can read maps generated by the Wayfinder skill?

## Answer

A Wayfinder **Map** on disk is `.scratch/<effort>/map.md`. Its children are `issues/NN-slug.md` (`Type:`, `Status:` empty/claimed/resolved, `Blocked by: NN, NN`), plus optional `research/NN-slug.md`, `spec.md`, and `prototypes/**`. Discover maps by globbing `map.md`; show that Effort’s files as a filesystem tree (not a blocking graph). Sibling `.scratch/` folders with only `spec.md` or `/to-tickets` issues are **not** maps — still list them so dnd-heiyuki specs and sealbox `first-slice` are visible. GitHub/GitLab maps are issues labelled `wayfinder:map` with `wayfinder:<type>` child issues (sub-issues / `Part of #n`, native blockers, assignees) — **nothing on disk**. Khaled’s maps are local-markdown-only; v1 of the Reader should scan/parse/show that layout and defer `gh`/`glab`.
